# ADR-0015: 미니앱 휴식 알림 — 화면 유지와 세션 내 타이머, 잠금 푸시는 실기기 실험

- **상태:** Accepted (2026-09-11, 해결 방법 확인 후 사용자 작업 진행 요청) · 잠금 푸시 서버 연동은 채택하지 않음, 결정 4·5의 검증 도구·동의 버튼·가이드는 삭제 → [D52](./mvp-decision-log.md#d52) (2026-09-14) · 결정 3 의 「숨김 상태에서는 오디오 예약을 중지」는 대체 — 숨겨도 예약을 남긴다 → [D70](./mvp-decision-log.md#d70) (2026-09-22) · 결정 3 의 「1초 이상 지연된 진동은 버린다」는 숨긴 동안 5초로 → [D72](./mvp-decision-log.md#d72) (2026-09-22)
- **대체 범위:** 백로그 024 §3.2(D52로 삭제)의 종목을 떠나면 휴식을 취소하던 동작. Flutter의 알림 결정은 바꾸지 않는다.

## 배경

웹 오디오 시계는 기기 잠금·백그라운드에서 멈출 수 있다. 화면의 종료 시각과 오디오 예약 시각이 달라지면 복귀 후 지난 알림이 울린다. 공개 토스 SDK의 `Notification`은 수신 동의 API이며, 로컬 알림을 예약·취소하는 API는 확인되지 않았다. 서버 기능성 푸시는 가능하지만 초 단위 도착을 보장하는 타이머는 아니다.

## 결정

1. 운동 기록 화면 전체에서 `Screen.setAwakeMode`로 자동 꺼짐을 막고, 화면을 나갈 때 해제한다. 앱 복귀 시 다시 적용한다. 요청이 실패해도 기록은 계속한다. 수동 잠금·백그라운드 실행을 보장하지 않는다.
2. 휴식은 운동 세션당 하나다. 목록·다른 종목으로 이동해도 유지하고, 다른 종목의 휴식이면 바에 종목명을 표시한다. 새 세트의 휴식은 앞 예약을 대체한다. 해당 세트 완료 취소, 건너뛰기, 통증 중단, 저장 시작, 운동 화면 종료는 예약을 취소한다.
3. 종료 시각은 `Date.now()` 기준이다. 숨김 상태에서는 오디오 예약을 중지하고, 복귀 시 남은 시간으로 다시 예약한다. 이미 끝난 휴식은 뒤늦게 울리지 않는다. 백그라운드에서 JS가 동작하면 진동은 시도하되 1초 이상 지연된 진동은 버린다. 오디오 `resume()`이 늦게 완료돼도 취소한 예약을 되살리지 않는다.
4. 잠금 푸시는 검증 도구까지만 준비한다. PC에서 토스의 테스트 메시지 API를 호출해 기기 잠금·앱 전환 중 수신을 측정한다. 전용 템플릿 `burnweek-rest-ended`, 테스트 번들 UUID, 사용자 동의가 필요하다. 기본 실행은 dry-run이다. 일반 앱에는 서버 예약 엔드포인트·Cloud Tasks 큐를 추가하지 않는다.
5. 테스트 동의 버튼은 `VITE_REST_PUSH_PROBE=true` 번들의 설정에만 표시한다. 이 버튼은 수신 동의만 받고 휴식을 예약하지 않는다. 일반 배포 번들에서는 플래그를 지정하지 않는다.

## 결과와 검증

- 기존 `PerformedSession`·주간 플랜·운동 수치와 API 계약은 그대로다. 휴식은 세션 화면을 나가면 종료되며 앱 재실행 후 복원하지 않는다.
- `miniapp/rest-check.mjs`는 360·390px에서 세션 내 이동, 연장·취소, 복귀, 늦은 오디오 응답, 화면 유지 요청의 실패·해제 순서를 검증한다. 소리 자체는 실기기 확인이 필요하다.
- 잠금 푸시 실험 절차는 휴식 알림 실기기 검증 가이드(D52로 삭제). 실제 수신 지연과 누락을 보고 서버 연동 채택 여부를 별도 결정한다. 기존 ‘3초 전부터 삐·삐·삐’와 서버 푸시의 동작을 같다고 약속하지 않는다.

- [토스 스마트 발송](https://developers-apps-in-toss.toss.im/documentation/common/growth/smart-message): 템플릿 검수·테스트 번들 발송·사용자 식별키별 분당 10회 제한.
