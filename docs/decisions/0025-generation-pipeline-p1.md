# ADR-0025: 생성 파이프라인 P1 — 코드 골격 + 슬롯 채우기 + 이유

## Status

Accepted (2026-10-14, [D103](./mvp-decision-log.md#d103)). [ADR-0016](./0016-generation-timeout-and-compact-draft.md)의 compact 초안 스키마를 P1 전환 시점에 부분 대체한다. 전환 전까지 ADR-0016 이 운영 경로다.

## Context

지금 LLM 은 영어 id 46~95개만 보고 약 40줄의 규칙(분할·순서·패턴·종목 수·`rep_intent`·입문자 바벨 제한)을 지키며 운동을 고른다. 추론을 끄면 하드 게이트 통과가 32/36에서 17/36으로 떨어졌다(ADR-0016). 하드 게이트는 규칙 위반을 세므로, 추론은 「잘 고르기」보다 「규칙 지키기·id 해독」에 쓰이고 있다. 사용자는 속도보다 판단을 우선했다. 근거: 백로그 09 §2.

## Decision

- **코드가 정한다(INV-1):** 분할·요일(기존) · 세션별 움직임 패턴 슬롯 · 종목 수 · 렙(복합/고립·목표·경험) · 슬롯별 후보 순위(큐레이션) · 맨몸 `requires` 필터.
- **LLM 이 정한다:** 슬롯마다 후보 표(`id | 한글명 | 장비 | 주근육 | 복합/고립 | 난이도 | 요구 도구 | 최근 이력`)에서 1개 · 한 줄 이유 · 대체 1~2개 · 주간 메모. 판단 대상은 목표 조합, 사용자 요청, 교체·추가 이력, 다양성과 연속성의 균형이다.
- **출력 검증:** 슬롯 후보 밖 id 는 버린다. 이유·메모의 숫자는 지운다(INV-1). 스키마 변경은 [02-data-model](../architecture/02-data-model.md)과 계약을 함께 고친다.
- **전환:** 플래그로 P0 와 P1 을 나란히 두고, 2차 실측(D103 ②)에서 P1 이 하드 게이트·판단 품질 기준을 넘으면 기본값을 바꾼다.
- **P2(검토 패스)·P3(템플릿만)** 은 이 결정에 넣지 않는다. P1 실측 결과가 기준에 못 미칠 때 다시 정한다. 서킷(D102)은 코드 템플릿이다.

## Consequences

- 프롬프트가 「역할 경계 + 판단 기준 + 출력 형식」으로 줄고, 추론 강도를 낮춰도 품질을 기대할 수 있다.
- 슬롯·운동 메타데이터·큐레이션 순위를 코드가 관리해야 한다(백로그 02·04 데이터 정리와 같은 작업).
- 모델 교체는 이 구조 위에서 비교한다. 1차 실측(P0·P0+표)은 모델 기본 실력과 메타데이터 효과를 보는 것이고 최종 선택이 아니다.

## Validation

운동플랜 개선 실행 그래프 N3(하드 지표·심판 하네스) · N8a·N8b(골격·슬롯·플래그 동등) · N9(2차 실측).
