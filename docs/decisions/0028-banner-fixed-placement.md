# ADR-0028: 배너 광고를 고정한다 — 탭·기록 화면은 하단 바 아래, 하위 화면은 위

## Status

Accepted (2026-10-21, [D109](./mvp-decision-log.md#d109)). 대체하는 것: [D91](./mvp-decision-log.md#d91)의 위치 규칙 전부 — 「본문 맨 끝」 · 「오늘 운동 결과는 결과 목록과 「메인으로」 사이」 · 「고정 배너는 쓰지 않는다 · 기록 화면은 `session-gap` 앞」 · Q1 「설정은 면책 바로 위」. [ADR-0022](./0022-exercise-detail-banner.md)의 「설명 뒤 본문 맨 끝」. [ADR-0023](./0023-ui-input-and-information-hierarchy.md) 대시보드 순서의 마지막 「광고」와 「D91·D96 의 광고 배치 유지」 중 배치 부분(실패 처리는 유지). 설정의 면책 전문은 여전히 최하단이다(R11). 화면당 1개·대상/제외 화면·덮는 화면 숨김·광고 ID·광고 없음 접힘은 D91 그대로다.

## Context

토스 콘솔 실측(2026-10-07~19)에서 배너 요청 666건 중 노출은 365건(55%)이었다. 본문 끝 배너는 사용자가 끝까지 내려가지 않으면 노출되지 않는다. 사용자가 레퍼런스 앱 3장(화면 위·아래 고정)을 보여 주며 고정 배치를 요청했다. 처음에는 제안 문서(백로그 `광고_위치_고정` · 삭제 2026-10-22 · 마지막 `e4386418`) §5 권고안(위 고정 · 띠 위아래 24px)으로 구현했다. 테스트 번들 `20261021-86` 을 실기기에서 본 사용자가 「별로야. 하단바 아래에 옮겨봐 … padding 이 너무 넓어」라고 했고, 시험 번들 `-88`~`-91` 을 거쳐 아래로 정했다(2026-10-21~22). 앱인토스 웹뷰 배너 문서는 고정형(높이 96px 권장, 컨테이너 폭 = 화면 폭)을 허용하고 버튼 인접·같은 형식 2개·가림·주기 새로고침을 금지한다. 인접 거리 수치는 문서에 없다.

## Decision

- **탭 5개**(대시보드·운동목록·플랜·체중·설정): 배너를 **탭바 아래 화면 맨 밑**에 고정한다(`position:fixed; bottom:0`). 홈 인디케이터 몫(`--sab`)은 배너가 지고, 탭바·교체 목록·종료 안내·본문 끝 여백은 배너 높이(`--ad-dock`)만큼 올라간다.
- **운동 기록 화면**: 배너를 **하단 완료 바 아래 화면 맨 밑**에 고정한다. 완료 바와 본문 끝 여백(`session-gap`)이 그만큼 올라간다.
- **하위 화면**(기록 내역·꾸준함과 성장·주간 리뷰·오늘 기록): 화면 머리 바로 뒤 첫 본문에 두고 `position:sticky; top:0` 으로 위에 고정한다.
- **운동 상세**: 머리(←·제목)와 배너를 한 sticky 묶음으로 둔다. ADR-0021의 「제목과 뒤로 버튼은 위에 유지」를 지킨다.
- **배너 영역.** 형식은 `expanded`(화면 너비를 채운다 · 좌우 여백·둥근 모서리 없음)이고 위아래 여백은 0이다. 광고가 오기 전에는 96px 자리를 잡아 두고(늦게 뜨며 본문을 밀면 오클릭이 난다), 광고가 그려지면 실제 높이(`--ad-h`)에 맞춘다.
- **키보드가 열리면** 배너를 숨기고 하단 바를 원래 자리로 내린다. 기록 화면의 통증 중단 안내(INV-6)는 키보드 위에 남는다. 덮는 화면(`.picker`·시트·`<dialog>`)이 열리면 숨기는 D91 규칙은 그대로이고, 플랜의 끌기 미리보기(`.drag-ghost`)가 떠 있는 동안에도 숨긴다.
- 새로고침 코드를 넣지 않는다. 새 노출은 SDK 의 자동 갱신(렌더 10초 뒤 화면 복귀)뿐이다.
- 전면형 광고는 이번에 넣지 않는다(제안 Q3 보류).

## Consequences

탭바와 기록 화면의 「세트 완료」 바 바로 아래에 광고가 붙는다. 앱인토스가 금지하는 「상호작용 요소와 인접해 의도치 않은 클릭을 유도하는 구조」에 해당할 수 있다는 것을 사용자에게 알렸고, 사용자가 이 배치를 골랐다(2026-10-21). 검수 반려·제재 신호가 오면 이 결정을 먼저 다시 연다. `check.mjs` 가 화면별 수량·위치와 CSS 고정·접힘 규칙 목록을, `startup-check.mjs`·`ui-check.mjs`·`rest-check.mjs` 가 상세 묶음·탭 화면 맨 밑 고정·`expanded` 형식을 검증한다. 광고 높이 맞춤(`--ad-h`)은 실제 광고에서만 돌아 브라우저 검증이 없다 — 실기기로 본다. 효과는 출시 뒤 콘솔의 노출/요청 비율(기준 55%)로 본다.
