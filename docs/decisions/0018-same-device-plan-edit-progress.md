# ADR-0018: 같은 기기에서 고친 플랜의 진행은 확인 없이 이어 간다

- **상태:** Accepted (2026-10-02, 사용자 요청)
- **대체:** [ADR-0017](./0017-miniapp-progress-cloud-drafts.md) 결정 3 가운데 「운동 중 직접 편집한 요일만 기기 입력을 이어 쓴다」. 다른 기기 수정은 자동으로 합치지 않는다는 결정 1은 유지한다.

## 배경

주간 플랜을 고친 뒤 운동을 시작하거나, 나갔다가 다시 들어오면 `plan_replaced`로 닫힌 초안과 이 기기 진행이 같아도 「진행 기록 확인」이 떴다. 이어 쓰기는 운동 화면을 연 채 편집할 때만 붙었고, 주간 플랜 편집에는 그 표시가 없었다. 다른 기기가 남긴 다른 진행까지 묻지 않고 덮으면 안 된다.

## 결정

1. 이 기기에서 성공한 비파괴 편집(빈 주·하루 비우기·요일 교환 제외)은 그 요일에 `plan_id`와 `generated_at`을 로컬 표시로 남긴다. 이어진 같은 기기 편집으로 세대가 바뀌면, 직전 세대와 정확히 같던 다른 요일 표시만 새 세대로 넘긴다. 이미 어긋난 표시는 되살리지 않는다. 플랜이나 세대가 다르면 표시를 지운다. 진행을 지울 때도 표시를 지운다. 빈 주·하루 비우기·교환한 요일은 넘긴 뒤에도 표시를 지운다.
2. 나중에 그 요일을 열 때 표시가 맞고, 닫힌 초안이 같은 `plan_id`의 `plan_replaced`이며, 처음 연 기기 진행이 그 초안과 같거나 초안에 입력이 없으면 확인 화면 없이 `start_after_retire`로 기기 진행을 이어 쓴다. 이 허가는 같은 입장에서 조회가 끊겼다 다시 시도할 때도 유지한다. 조회를 기다리는 동안 늘어난 입력은 그 초안과 달라도 다른 기기 수정이 아니다. 초안 내용이 처음 연 진행과 다르면 확인 화면을 유지하고 어느 쪽도 지우지 않는다.
3. 운동 화면을 연 채 한 편집은 종전처럼 그 자리의 기기 입력을 바로 잇는다.
4. 이어 쓰는 진행은 종목 ID를 유지한다. 뺀 종목의 입력은 다른 종목으로 옮기지 않는다.

## 결과

- 서버는 옛 초안을 `progress_draft_archives`에 보관한 뒤에만 새 초안을 쓴다. API 계약의 그 조건은 그대로다. 클라이언트 이어 쓰기 조건은 생성 API 계약 §2.4.1에 있다.
- 표시가 없는 다른 기기의 플랜 변경, 그리고 내용이 다른 진행은 확인 화면이 남는다.
