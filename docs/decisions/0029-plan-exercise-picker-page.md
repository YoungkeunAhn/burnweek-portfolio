# ADR-0029: 주간 플랜 운동 추가·변경을 독립 페이지로 전환

## Status

Accepted (2026-10-23). 사용자 실기기 보고와 페이지 이동 요청에 따른다. 주간 플랜의 운동 고르기를 고정 오버레이로 표시하고 탭바 위에서 끊던 동작을 대체한다. [ADR-0028](./0028-banner-fixed-placement.md)의 탭 화면 광고 배치는 유지한다.

## Context

운동 추가 화면은 주간 플랜 안의 고정 오버레이였다. 부위 선택은 고정되고 결과 목록만 스크롤했다. 키보드가 열려 탭바·광고가 숨겨져도 하단 여백이 남아 검색 결과가 잘리고 뒤쪽 주간 플랜이 드러났다.

## Decision

주간 플랜의 운동 추가와 편집 시트의 다른 운동으로 변경은 App이 소유하는 별도 `main`으로 이동한다. [운동 상세 페이지](./0021-exercise-detail-page.md)와 같은 React 상태 기반 탐색 및 토스 뒤로가기 스택을 사용한다. 모달 역할·고정 위치·목록 내부 스크롤을 제거하고 부위 선택부터 결과까지 문서 전체가 스크롤한다.

출발 주간 플랜은 마운트를 유지한 채 `hidden`으로 레이아웃·접근성 트리·탭 순서에서 제외한다. 선택 페이지에는 하단 탭바와 광고를 표시하거나 그 자리를 예약하지 않는다. 진입 시 문서 맨 위와 선택 페이지로 포커스를 옮긴다. 상단 뒤로 버튼과 토스 뒤로가기는 선택 요일·스크롤·출발 버튼 포커스를 복원한다.

종목 선택 뒤 플랜으로 돌아가 기존 `add`·`replace` 요청을 수행한다. 빈 주 준비, 검색 조건, 후보 필터, 실패 안내, 운동 수치의 코드 소유는 유지한다. 운동 기록 중 `swap`은 이번 변경 범위에서 제외한다.

## Verification

`picker-check.mjs`에서 360·390px 문서 스크롤, 부위 선택과 결과의 동시 이동, 키보드 높이 축소 후 마지막 결과 선택을 검사한다. `startup-check.mjs`에서 실제 App의 추가·변경 진입, 플랜·탭바·광고 숨김, 두 뒤로가기 경로, 요일·스크롤·포커스 복원 및 편집 요청을 검사한다. 토스 실기기 키보드 확인은 별도다.
