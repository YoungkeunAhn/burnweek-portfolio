# ADR-0030: 최근 4주 운동별 수행 기록으로 처방

## Status

Accepted — 2026-10-26 사용자 승인. [D22-6](./mvp-decision-log.md#d22)의 직전 주 입력과 [D57 A10](./mvp-decision-log.md#d57)의 유산소 이력 조회 범위를 부분 대체한다. 수치 소유권·통증 규칙·사용자 지정 목표 우선순위는 유지한다.

## Context

직전 주 문서 하나만 읽으면 격주로 하는 운동은 기록이 있어도 첫 주 처방으로 돌아간다. 반대로 과거의 상단 달성 기록에 증량을 그대로 적용하면 한 주 이상 쉬고 돌아와도 무게나 맨몸 단계가 올라간다. 사용자는 최근 4주에서 운동별 최근 수행을 선택하고, 지난주 미수행 운동의 자동 상승을 보류하는 기준을 승인했다.

## Decision

1. 서버가 자기 계정의 대상 주 이전 **28일**에 시작한 주차 문서를 읽는다. 문서 개수가 아니라 달력 범위다. 이번 주·미래 주·다른 계정은 제외한다. 세션 날짜도 소속 주의 7일 안이면서 대상 주 이전이어야 한다. 날짜가 없는 옛 세션은 소속 주와 `day_index`로 복원한다.
2. 같은 `exercise_id`마다 **가장 최근 세션 하나**의 세트를 사용한다. 빈 목록·워밍업만 있는 세션은 수행으로 세지 않는다. 실패한 워킹 세트는 수행에 포함한다. 서로 다른 주나 세션의 최고 중량·달성률을 합치지 않는다. 같은 날짜는 요일·소속 주·저장 요일 순서로 결정한다.
3. 근력·맨몸은 기준 수행일이 대상 주 시작 7일 전보다 이르면 자동 증량·맨몸 사다리 상승을 보류한다. 근력은 기록의 워킹 중량을 유지하고 `hold/history_gap`으로 설명한다. 통증·실패에 따른 기존 감량·교체·맨몸 하향은 우선한다. 지난주 수행한 운동의 기존 목표별 증량 규칙은 유지한다.
4. 유산소도 같은 범위에서 최근 기록의 설정을 복사한다. 자동으로 시간·강도를 올리지는 않는다. 사용자가 직접 정한 목표가 항상 우선한다(D57 A11).
5. AI 생성과 새 수동 주에 같은 선택 함수를 쓴다. 선택된 날짜·세트를 `prior_logs`에 저장하고 편집에서는 그 스냅샷을 다시 쓴다. 이미 저장된 주를 다시 조회해 과거 기록을 보충하는 마이그레이션은 하지 않는다. 날짜 없는 기존 스냅샷의 진행 동작은 유지한다.
6. `WeeklyPlan v1.progression_decision`에 사유 `history_gap`과 선택 필드 `source_date`를 추가한다. 미니앱은 기존 진행 사유 자리에 보류 이유와 기준 날짜를 표시한다. LLM에는 기존 비수치 선택 신호만 전달한다.

## Consequences

- 격주 운동은 최근 수행 중량에서 이어지고, 공백 이후 자동 상승은 막힌다. 4주 범위 밖의 기록만 있으면 기존 첫 기록 없음 처방을 따른다.
- 정체 감지·주기적 디로드·램프업 자동 판별·난이도 피드백은 이 결정에 포함하지 않는다.
- 기존 오름차순 문서 조회를 재사용하므로 새 Firestore 색인은 필요 없다. 계정의 주차 문서를 읽은 뒤 범위를 고른다. 문서가 많아지면 조회 범위를 서버 질의로 제한하는 최적화가 필요하다.
- 계약은 generation-api, 스키마는 [02-data-model B2](../architecture/02-data-model.md), 구현·검증 이력은 변경 기록을 따른다.
