# ADR-0027: 운동 제작 원본은 Drive에 보관하고 일반 빌드에서 분리한다

## Status

Accepted (2026-10-19). 사용자가 pull 지연을 줄이기 위해 지정한 Google Drive 폴더로 제작 자료를 이전하고 폴더·파일명도 재정리하도록 요청했다.

## Context

[ADR-0026](./0026-exercise-media-on-r2.md)으로 앱 재생은 R2로 전환했지만 제작 자료 약 8.63GiB가 최신 Git 트리에 남았다. 일반 빌드도 원본 전체의 metadata·Blender 파일을 읽었다. 새 PC의 체크아웃에는 Git에서 제외된 일부 원본이 없어 원본 검사가 이미 실패했다.

## Decision

- Drive에는 `01_운동라이브러리/운동분류/한글운동명__고유ID/`로 현재 앱 연결 자료를 정리한다. 영상·대표·시작·종료 파일명은 한글명, 역할, 내용 해시 12자리로 구성한다. R2의 기존 주소는 바꾸지 않는다.
- 제작 자료 전체는 `90_제작원본`의 ZIP에 내부 경로 그대로 보관한다. 저장 전후 모든 파일의 SHA-256과 ZIP의 SHA-256을 검증한다. 조사·시행착오·검토 이력·미추적 파일도 보존하고 전문 검수 상태를 변경하지 않는다.
- Git에는 앱 코드, 생성 인덱스, 작은 릴리스 증거, 근육 도해 배포 자산, 제작 문서를 남긴다. 대용량 원본·렌더·검토 산출물은 추적하지 않는다. 문서가 인용한 이전 제작 파일은 이전 커밋의 고정 링크로 찾는다.
- 일반 `build`는 `exercise-media-release.json`과 생성 인덱스의 SHA-256, 전체 ID, 카탈로그, R2 해시 주소, 재생 metadata를 검사한다. 근육 도해는 릴리스 manifest와 실제 public 자산 해시를 검사한다. Drive나 네트워크 없이 빌드할 수 있다.
- `check:exercise-media:source`, `check:muscle-atlas:source`, 생성·업로드는 `BURNWEEK_MEDIA_SOURCE_ROOT`로 지정한 외부 원본을 검증한다. 원본 검사를 생략하거나 누락 파일을 성공으로 처리하지 않는다. 원격 HEAD 검사는 릴리스에 기록된 MD5를 사용한다.
- 최초 이전에서는 기존에 커밋된 757종 인덱스에 대해 실제 배포 파일 3,028개와 metadata 757개의 SHA-256을 대조해 릴리스 증거를 만들었다. 기존 전체 원본 검사의 누락 Blender 파일 오류는 별도 기록한다. 이는 전체 제작 파이프라인 검증 성공을 뜻하지 않는다.

## Supersedes

[ADR-0026](./0026-exercise-media-on-r2.md)의 일반 `--check`/build가 제작 원본을 직접 검증하던 부분만 대체한다. 전체 원본 검증은 `--check-source`로 유지한다. R2 제공, immutable 해시 URL, 업로드 사전검사, 앱 재생 규칙은 유지한다.

## Consequences

다음 커밋의 작업 트리와 이후 자료 변경의 전송량이 줄어든다. 과거 Git 이력은 자동으로 줄지 않으며 force push나 이력 재작성은 이 변경에 포함하지 않는다. 새 PC는 변경이 원격에 반영된 뒤 shallow clone으로 과거 대용량 이력을 생략할 수 있다.

재제작할 때는 Drive ZIP을 별도 작업 폴더에 풀어야 한다. 기존 누락 원본 복구가 필요한 묶음은 엄격한 원본 검사에서 계속 실패한다. 절차와 파일명 규칙은 외부 제작 자료 가이드, 이전 증거는 보관 영수증에 둔다.
